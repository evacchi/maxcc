# Chapter 1: one thread, one store

```
kernel answer(out: *u32) {
    *out = 42;
}
```

Done when the GPU prints `param 0 = 42`.

## Pipeline

```
source --lex--> tokens --parse--> L0 (ast.rs) --select--> L-ptx (ptx.rs) --emit--> .ptx
                                                ^^^^^^
                                                 you
```

Inspect each stage: `cargo run -- --lex|--parse|--select examples/answer.k`.

## Read first

PTX ISA (https://docs.nvidia.com/cuda/parallel-thread-execution/):
- §5.1 State Spaces: `.param` and `.global`.
- §6.4 Generic addressing.
- §9.7.9 Data movement: `ld`, `st`, `mov`, `cvta`.

## Task

Write `select.rs`. Per kernel parameter and per store, decide:

1. Where does the pointer live when the kernel starts? How do you get it
   into a register? Name the `.param`s like `<kernel>_param_<i>`.
2. The host passed a *generic* address. `st.global` wants a *global*
   one. Convert it, or use generic `st` (needs a new `Space` variant).
   Try both later.
3. Store the value. Can the source be an immediate, or must it be a register?
4. End the kernel.

You decide how to number registers.

`ref/answer.ptx` is clang's output (`ref/ptx.sh ref/answer.cu`). Compare
with it only after your version runs. It doesn't have to match.

## Run

All examples, end to end: `GPU=user@host tests/gpu.sh`.

One by hand:

```
cargo run -q -- examples/answer.k > answer.ptx
scp answer.ptx runner/run.c gpu:
ssh gpu 'cc run.c -o run -I/usr/local/cuda/include -lcuda && ./run answer.ptx answer'
ssh gpu 'ptxas -arch=sm_70 -v answer.ptx -o /dev/null'   # validate + register count
```

## Questions to answer before chapter 2

- Why is the parameter a 64-bit value when the kernel stores a 32-bit one?
- Remove the `cvta` but keep `st.global`. What happens? Why?
- `.reg` declares *virtual* registers. Who allocates the real ones?
  (Hint: what does `ptxas -v` report? Also see `cuobjdump -sass`.)
- 3 parameters, `*a = 1; *b = 2; *c = 3;`: run with `./run x.ptx k 3`.
